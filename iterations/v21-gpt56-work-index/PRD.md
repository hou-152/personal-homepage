# V21 GPT-5.6 Work Index PRD

## 1. 迭代目标

把 V20 的「AI 作品证据 Dashboard」收束成一份更像个人主页的「编辑式工作索引」。

V21 不再通过重复模块制造证据密度，而是通过编辑权重建立可信度：

- 首屏先讲侯斯博本人和核心工作判断。
- 一个强项目只完整讲一次。
- 次级项目只保留一句定义、一条真实证据和一个有效入口。
- 未完成、无公开证据或涉及隐私的项目诚实降权或不公开。

本轮采用用户已确认的 GPT-5.6 原创设计方向：暖白底、近黑文字、橙红信号色、编辑式索引结构。

## 2. 已确认事实

以下事实来自当前项目代码、项目文档和 2026-07-20 的线上实测：

- V20 首页有 7 个主要 section、26 个 article 和 42 个主内容链接。
- V20 桌面首页总高约 8438px。
- 390 × 844 手机首页总高约 17658px，约 20.9 屏。
- 手机 Hero 高约 2376px，Projects 区高约 7061px。
- 《serious AI 内参》当前在 Hero、三案例墙、Featured 卡和 Delivery Proof 中重复出现。
- 当前 `projects.ts` 有 6 个项目：个人主页、微信 ClawBot、微信对象库 / RAG 原料层、碳水蛋白质配额卡、个人公众号、思想孵化 Agent。
- `growth.ts` 当前表达的是工作方法，不是真实的时间成长线。
- `abilities.ts` 和 `workbench.ts` 当前没有在首页渲染。
- 微信 ClawBot、个人公众号和思想孵化 Agent 当前使用 `#workbench` 作为 Demo 入口，但首页没有对应区块。
- Build Log 当前有 30 条记录，分布在 7 个活跃日期。
- `global.css` 当前约 3440 行，包含基础样式、V19 覆盖和 V20 覆盖。
- 根目录当前没有 `SOURCE_OF_TRUTH.md`。
- `3775 articles` 当前只在首页组件中硬编码，尚未找到对应的数据权威来源。

## 3. 问题判断

### 3.1 内容问题

V20 的主要问题不是项目不足，而是同一批项目被反复解释。

重复造成三个后果：

- 最强证据被稀释，访问者需要自行判断哪些内容最重要。
- 页面高度和链接数量失控，手机端阅读成本过高。
- 项目越多，主页越像内部工作台，不像能快速转发的个人作品页。

### 3.2 视觉问题

V20 的 Swiss 网格建立了秩序，但右侧大型作品 Canvas 在手机端被完整拆成纵向长页，首屏无法在一屏内完成理解。

V21 不再追求「更多证据块」，而是追求：

- 更少的容器。
- 更明确的项目权重。
- 更像作者编辑过的作品索引。
- 更短、更容易扫读的移动端路径。

### 3.3 数据问题

公开仓库存在，只能证明仓库和公开材料存在，不能自动证明用户完成了其中所有工作。

任何新增项目在上线前都必须补齐：

- 用户的具体角色。
- 用户实际完成的动作。
- 可公开引用的结果。
- 可核验入口。
- 不应公开的第三方信息和私密材料。

## 4. 产品定位

V21 是一份面向家人、老师、朋友、老板和潜在合作方的个人工作索引。

它不是：

- AI 产品官网。
- 项目管理 Dashboard。
- 传统简历。
- GitHub 仓库目录。
- 私人工作台公开镜像。

它要让访问者在 10 秒内理解：

1. 侯斯博关注什么问题。
2. 他把这些问题做成了哪些系统、Skill 和工具。
3. 哪些作品可以被直接验证。

## 5. V21 首页信息架构

首页收束为 4 个主要区段。

### 5.1 Hero：侯斯博与核心判断

目标：先建立人物和方向，不在首屏展开完整项目案例。

冻结文案方向：

> 我把散落的信息，做成可以工作的系统。

副标题方向：

> 从 AI 信息流、知识加工到内容工程，我把模糊问题拆成流程，再推进成 Skill、Demo 和公开作品。

首屏内容：

- 侯斯博 / Da Capo。
- 一句核心判断。
- 一句工作范围。
- 「看精选作品」和「GitHub」两个主要入口。
- 右侧 4 行 Project Index，不再放大型 AI 内参 Canvas。

### 5.2 Selected Work：精选作品

冻结为 1 个主案例和 3 个支持项目。

#### 主案例

1. 《serious AI 内参》
   - 首页只完整表达一次。
   - 保留一句项目定义、一条核心工作流和最多 2 个入口。
   - 完整流程、录屏和证据进入现有 case 页。
   - `3775 articles` 未核源前不进入 V21 首页。

#### 支持项目

2. 本地提取微信聊天记录。
3. 碳水蛋白质配额卡。
4. AI 视频流水线。

本地提取微信聊天记录使用以下已核对口径：

- 在本机以只读方式提取微信聊天记录。
- 当前可处理文字、链接和文章卡片，并把原始输入送入本地清洗与后续结构化流程。
- 原始聊天、会话 ID、数据库密钥、身份映射和私有处理结果不进入公开页面或构建产物。
- 首页只展示工作流和隐私边界，不展示聊天原文或导出数据。

AI 视频流水线使用以下已核对口径：

- 面向中文 16:9 解释型视频。
- 从 DBS 已确认并冻结的文案开始，接管配音字幕、全时间线视觉、Remotion 迭代、低清 proof 和 QA。
- 默认交付低清 proof；正式成片仍需独立人工确认和导出授权。
- 不声称覆盖实拍、电影级人物表演、复杂 3D / VFX、事实核查、法律清权或传播效果。
- 公开 Demo、案例页或可分享 proof 入口仍待确认，未确认前不使用失效或虚构链接。

支持项目统一使用紧凑编辑式条目：

- 项目名。
- 一句话说明。
- 一条真实证据。
- 一个主要入口，必要时最多增加一个次级入口。

不在首页重复完整的「问题 / 动作 / 证明 / 技术栈 / 功能列表」。

### 5.3 More Work + Build：更多工作与最近交付

More Work 使用单行索引，不使用完整项目卡。

候选项目：

- Publication Engineering Workflow。
- Content Engine。
- WeChat Relationship Corpus Skill，默认只进入 Lab 层级。
- 个人主页本身，只在页脚说明从 Brief 到 V21 的构建过程，不再作为首页项目卡。

Build 区不再展示大面积热力图。它收束为：

- 一句工作方式。
- 最近 3 次有效交付。
- 当前版本和 GitHub 入口。

现有 Growth、Thinking、Delivery Proof 和 Build Heatmap 不再作为 4 个独立叙事区块。

### 5.4 Contact：联系与收束

保留：

- GitHub。
- Gmail。
- 微信。
- 本站构建说明。

电话号码是否继续在公开页可见，需用户单独确认；Phase 1 不修改 `links.ts`。

## 6. 项目增删与权重

### 6.1 保留并主推

- 《serious AI 内参》：唯一主案例。
- 本地提取微信聊天记录：本机只读提取、清洗和结构化流程；不公开聊天原文或私有运行数据。
- 碳水蛋白质配额卡：公开 Live Demo 和 GitHub 仓库。
- AI 视频流水线：从冻结文案推进到低清 proof 和 QA 的受控解释型视频生产线；公开证据入口待确认。

### 6.2 新增到 More Work

- Publication Engineering Workflow。
- Content Engine。

两者上线前都要确认用户的具体贡献。Content Engine 中的文章数量、传播数据和第三方反馈不能直接从 README 搬到主页。

### 6.3 降权到 Lab / Now

- 微信 ClawBot。
- 个人公众号。
- 思想孵化 Agent。
- WeChat Relationship Corpus Skill。

没有独立公开证据的项目不提供失效 Demo 按钮。

### 6.5 从首页项目区删除

- 个人主页完整项目卡。
- 重复的 AI 内参三案例墙和 Featured 卡。
- 独立 Work Thinking 区。
- 独立 Delivery Proof 区。
- 大面积 Build Heatmap。
- 指向不存在区块的 `#workbench` Demo 入口。
- `jiaoliu` chat export。

删除首页展示不等于删除数据文件或历史记录。后续执行时，未使用内容先保留在数据层，除非用户明确授权清理。

## 7. 隐私与证据边界

### 7.1 永远不公开

- 微信原始聊天。
- 解密数据库。
- 身份映射。
- 私有仓库 README 或实现细节。
- API 密钥、配置文件和本机路径。
- 未经授权的第三方姓名、评价和内部数据。

### 7.2 默认不进入首页

- `wechat-thought-incubation-agent` 的私有内容。
- `logseq-all` 的私有内容。
- `jiaoliu` chat export。
- WeChat Relationship Corpus 的任何真实聊天原料。

### 7.3 可以公开但需要确认口径

- AI 视频流水线的公开 Demo、案例页或可分享 proof 入口。
- Publication Engineering Workflow 中用户的具体角色。
- Content Engine 的产出数量、传播数据和第三方反馈。
- 电话号码是否继续作为公开联系入口。

## 8. 范围

### In Scope

- 重构首页信息架构。
- 建立 V21 编辑式工作索引视觉系统。
- 删除首页重复叙事。
- 回填已确认的精选项目和 More Work。
- 修复无效项目入口。
- 更新版本和 Build Log。
- 桌面端和移动端验证。
- 同步 V21 设计规范和迭代文档。

### Out of Scope

- 改写 BRIEF 的长期定位。
- 更换 React、Vite 或普通 CSS 技术栈。
- 引入后台、数据库、登录或新设计依赖。
- 公开私有仓库内容。
- 公开微信原始语料。
- 自动推导用户贡献。
- 提交 Git。
- 部署线上版本。

## 9. 设计目标

以下为 V21 实施目标，不是当前事实：

- 首页主要 section 从 7 个压缩到 4 个。
- 主内容链接控制在 18 个以内。
- 移动端总高控制在约 8–10 屏。
- 390 × 844 手机 Hero 控制在约 1 屏，目标高度不超过 900px。
- 桌面端首页目标总高不超过约 4800px。
- 同一个项目事实在首页只出现一次完整表达。
- 所有可点击项目入口都指向真实存在的页面。

## 10. 验收标准

- 访问者在 10 秒内能说出侯斯博在做什么。
- Hero 先表达人物和判断，不再展开完整 AI 内参工作台。
- 首页只有一个完整 AI 内参主案例。
- 精选项目固定为 1 主 + 3 辅。
- More Work 不使用长卡片。
- 手机端不出现 6 步工作流逐条堆叠造成的超长首屏。
- 无 `#workbench` 失效入口。
- 未核实数字不出现在公开文案。
- 私有仓库和聊天语料不进入构建产物。
- `npm run build` 通过，或 blocker 被明确记录。
- 桌面和 390 × 844 手机截图完成视觉验收。
